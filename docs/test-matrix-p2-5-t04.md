# P2.5-T04 — Core test matrix

**Execution date:** 2026-08-26  
**Scope:** V1.0 Web MVP for THCS/THPT; synthetic, PII-free fixtures only  
**Contract boundary:** NestJS owns API/import/workflow validation; PostgreSQL is the source of truth; Redis/BullMQ owns durable jobs; Python/OR-Tools owns solver feasibility and hard constraints. React is a presentation/workflow surface, not a security or correctness boundary.

## Test levels

| Level               | Purpose                                                                                                                                     | Gate                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Unit/contract       | Fast assertions for domain rules, permissions, import validation, solver contracts and output contracts                                     | `npm run ci:local`                                                     |
| Integration/runtime | HTTP boundary against Docker PostgreSQL/Redis and local NestJS API; verifies persisted scope, status codes and response headers             | `node scripts/test-p2-5-t04-runtime.mjs`                               |
| E2E/UI              | Browser smoke markers and workflow controls; authenticated browser, target viewport and pilot workbook review remain separate release gates | `npm run ci:local` frontend smoke plus explicit browser/pilot evidence |

## Execution policy

- CI must execute the unit/contract matrix and fail on assertion failure; no `|| echo` or soft-fail wrapper is acceptable.
- Runtime integration is intentionally an explicit command because it requires Docker PostgreSQL/Redis and a running local NestJS API. The script uses only synthetic fixtures and may create one local confirmed import batch.
- E2E-02 is not inferred from static bundles or local headers. Production identity/session, staging, pilot workbook and stakeholder approval remain release gates.
- Any contract change across NestJS and Python requires a versioned schema/fixture update and a corresponding matrix row.
